# P16.33 T1 — Call-path decomposition (the shared ~+250 i/it call gap)

**Task**: P16.33 T0+T1 (research, no production changes). T0: fresh perf truth
(geomean, per-workload counters, code-size). T1: decompose the shared
~+250 i/it instructions-per-iteration gap that appears on BOTH ordinary Lua
calls (`lua_calls` +257.2) and direct metamethod calls
(`metamethod_call_noalloc` +246.6) — isolate TMS resolution from activation
cost, attribute the gap to exact VM components via callgrind, compare the
activation field-write flow against PUC Lua 5.5.0, and rank architectural
cut candidates.

**Provenance**: measured at git HEAD `fa75a87` (clean), zig 0.16.0
ReleaseFast (`zig_binary_sha16 d6ade010ff343708`), PUC lua 5.5.0
(`build/lua-c/lua`, `puc_binary_sha16 d54bc45e1757b216`), core 0 pinned via
taskset. T0 snapshot artifacts: `/tmp/opencode/p33_b0/{current,
current-counters,current-profile-index}.json`. Code-size artifact:
`tools/perf/current-p33-codesize.json`. Bench scripts:
`/tmp/opencode/t1bench.lua` (perf lane), `/tmp/opencode/t1cg_{plain,mm}.lua`
(callgrind lane, exact closure shapes).

## 2. T1-A — isolation benches (N = 5M, /tmp/opencode/t1bench.lua)

Three shapes, identical `bench()` harness (warmup n/100, os.clock), run
identically on both engines; instructions:u median of 3 via
`taskset -c 0 perf stat -e instructions:u -r 3`.

| bench | zig i/it | puc i/it | gap | zig_s | puc_s |
|---|---|---|---|---|---|
| `plain` — `local function f(x) return x end; s=f(s)` | 474.0 | 227.4 | **+246.6** | 0.136 | 0.062 |
| `mm` — metamethod_call_noalloc shape (`s = s + box`, `__add = function(a,b) return a end`) | 600.2 | 359.7 | **+240.5** | 0.215 | 0.086 |
| `samebody_nolookup` — same callee body/arity as mm (`g(a,b) return a end`), invoked as a normal Lua function | 520.4 | 248.6 | **+271.8** | 0.151 | 0.064 |

Derived deltas (the decomposition):

| delta | zig | puc | meaning |
|---|---|---|---|
| `mm − samebody_nolookup` | +79.8 | **+111.1** | TMS resolution (ADD fallthrough + MMBIN + `__add` hash lookup) + metamethod staging (`stageFixedCall` 3 stores vs PUC `luaT_callTMres` 3 setobj) |
| `samebody_nolookup − plain` | +46.5 | +21.2 | 2-arg vs 1-arg call (extra arg store + reg handling) |

**Finding 1 — the gap is NOT metamethod machinery.** zig's metamethod-specific
block (+79.8) is *cheaper* than PUC's (+111.1): the P16.29/P16.32
fixed-arity staging + shared `pushStagedFast` activation already beat PUC's
`callbinTM`→`luaT_callTMres`→`luaD_call` chain. No action needed on the
mm-specific components.

**Finding 2 — the whole ~+250 gap is present in the plain ordinary call.**
`plain` (+246.6) ≈ `mm` (+240.5) ≈ `samebody` (+271.8). The shared cost is
the ordinary CALL→activate→execute→RETURN cycle plus the generic per-opcode
dispatch overhead (plain executes 6 opcode fetches/iter: GETUPVAL, MOVE,
CALL, MOVE, FORLOOP in the caller + RETURN1 in the callee).

## 4. T1-C — PUC vs zig activation field comparison

### 4.1 PUC activation (luaD_precall LUA_VLCL, ldo.c:726-738 + prepCallInfo ldo.c:628-636)

Writes on EVERY Lua-function activation (5 memory writes total):

1. `L->ci = ci = next_ci(L)` — `ci->next` reuse (linked list; `luaE_extendCI` only on first-ever depth)
2. `ci->func.p = func`
3. `ci->callstatus = status` (nresults+1 packed in low 8 bits)
4. `ci->top.p = func + 1 + fsize`
5. `ci->u.l.savedpc = p->code`

Compare-only (no writes on the fast shape): `checkstackp(L, fsize, func)`
(1 compare, no growth), missing-args loop (`narg == nfixparams`, 1 compare).
OP_CALL prelude adds 2 writes: `L->top.p = ra + b`, `savepc(ci)` (caller's
savedpc). **NOT written at activation**: `u.l.nextraargs` (only vararg
paths), `u.l.trap` (only when hooks install, via `luaG_traceexec`),
`u2` (union, only yield/close paths), `previous/next` (persistent links).

### 4.2 PUC return (OP_RETURN1 fast, lvm.c:1810-1820 + `ret:` 1823-1229 + `returning:` 1207-1215)

2 writes + ~7 loads: `L->ci = ci->previous` (write), result setobj /
`L->top.p` (1 write + 1-2 movs), `ci->callstatus & CIST_FRESH` (compare),
then `returning:` = `trap = L->hookmask; cl = ci_func(ci); k = cl->p->k;
pc = ci->u.l.savedpc; base = ci->func.p + 1` (5 loads, **no stores** — all
resume state is frame-resident).

### 4.3 zig activation (`pushStagedFast`, vm.zig:12904-12984)

15 memory writes on EVERY activation:

| # | write | PUC activation-time equivalent |
|---|---|---|
| 1 | `exec_frames.inline_count = idx+1` (or heap.addOne) | `next_ci` reuse (no write) |
| 2 | `ef_slot.u = .{.lua = undefined}` (union tag) | — (no tag; CIST_C bit in callstatus) |
| 3 | `u.lua.proto = proto` | — (proto lives in the LClosure, no copy) |
| 4 | `u.lua.pc = 0` | `u.l.savedpc = p->code` ✓ |
| 5 | `u.lua.frame_cap = maxstacksize+MARGIN` | `ci->top.p = func+1+fsize` ✓ |
| 6 | `u.lua.nextraargs = 0` | **none** (PUC writes it only on vararg paths) |
| 7 | `u.lua.lua_packed_flags = 0` | **none** |
| 8 | `u.lua.simple_result_dst = 0xFF` | **none** (PUC passes `res` pointer to `luaT_callTMres`) |
| 9 | `func_slot = func_slot_in` | `ci->func.p` ✓ |
| 10 | `callstatus = encodeNresults(nresults)` | `ci->callstatus` ✓ |
| 11 | `reg_top = numparams` | **none** (PUC has one global `L->top`, no per-frame top) |
| 12 | `tbc_mark = bc_tbc_regs.items.len` | **none** (PUC tests `L->tbclist.p` against base on demand) |
| 13 | `tbc_chain_base = c_tbc_chain.items.len` | **none** |
| 14 | `pending_call_index = INVALID_PENDING` | **none** (PUC continuations live on the C stack) |
| 15 | `bc_stack_top = needed_top` | ≈ `ci->top.p` ✓ |

7 of 15 writes have **no PUC activation-time counterpart** — they eagerly
initialize state that PUC derives lazily or tracks globally. Plus shape
checks (`!is_vararg`, `nargs == numparams`), capacity checks (2 compares +
headroom rule), and the `dispatch_gate & HOOKS` test.

### 4.4 zig return (opReturn1 ordinary fast arm, vm.zig:16592-16703)

Writes: `child.callstatus = 0` (PUC: none — ci left as-is), `bc_stack_top =
parent base+cap` (≈ PUC top.p), `shrinkTo` count, result copy (≈ setobj),
`parent.pc += 1` (read-modify-write of heap field; PUC's pc is a local,
stored only at the next boundary), and the **ctx refresh**: 6 stores to the
ctx struct (`cur_proto`, `cur_upvalues` — a *dependent load* through
`bc_stack[func_slot].Closure.upvalues`, `base`, `frame_cap`, `pc`, `regs`
ptr+len slice construction). PUC's `returning:` does 5 plain loads, no
stores, and never touches upvalues (GETUPVAL reads `ci_func(ci)->upvals`
per access).

## 5. Ranked top-3 architectural candidates for the shared activation cut

### #1 — Per-fetch dispatch slimming to PUC `vmfetch` shape
**est. −55..−66 i/it on lua_calls (6 fetches), −45..−50 on mm (5 fetches), −20..−32 on arith/branch workloads — also explains most of the non-call gap (int_arith +48.5 for 2 fetches).**

zig pays 16.2 i/fetch: `while (ctx.pc < ctx.cur_proto.code.len)` (4.0 —
bounds compare + two loads per fetch), `inst = code[ctx.pc]` (2.0 —
recomputed pointer arithmetic), `self.dispatch_pc = ctx.pc` (1.0 — a memory
store per instruction), `dispatch_gate != 0` (3.0 — memory load + test),
`switch (op)` (6.1 — decode + jump). PUC pays ~5: register-local `trap`
branch (1), `i = *(pc++)` (2), `GET_OPCODE` + `goto *disptab` (2).

Mechanism (PUC-first, lvm.c:1185-1191 + lstate.h CallInfo `u.l.trap`):
- pc as a **pointer cursor** into the code array; loop exit only via RETURN
  opcodes (PUC's `for(;;)` has no per-fetch condition — the `while pc < len`
  is an index-dispatch artifact);
- `dispatch_gate` → PUC's **`trap` model**: a value cached in the dispatch
  frame, refreshed only at frame boundaries (`updatetrap`) and hook
  install — not a memory load per instruction;
- `dispatch_pc` published only at boundaries (PUC `savepc` at
  calls/returns/errors), not per instruction;
- verify the switch decode emits one extraction (PUC `GET_OPCODE` is a
  single mask).

### #2 — Frame-transition ctx re-derivation → PUC `startfunc`/`returning` parity
**est. −40..−50 i/it on every Lua→Lua call (and every metamethod call).**

zig pays ~55 per call cycle re-deriving decode state: 30.3 (child entry via
`continue :frame_loop` — pending-call check + 6 hot-field inits) + ~25
(parent resume inside the return arms — 6 ctx stores incl. the dependent
`cur_upvalues` load through `bc_stack[func_slot]`). PUC pays ~12 total:
`startfunc` (base = ci->func.p + 1) and `returning:` (5 loads into locals,
no stores, no upvalues caching — GETUPVAL reads the closure per access).

Mechanism: make the hot decode state frame-resident the way PUC's
`savedpc`/`cl`/`k` locals are — re-derive only `base` (+ trap) on
transitions; the CALL fast path's frame_loop re-entry and the return arms'
full ctx rebuild collapse to PUC's two gotos.

### #3 — Activation field-write reduction to PUC `prepCallInfo` parity
**est. −20..−30 i/it on every call, including every metamethod call.**

`pushStagedFast` performs 15 memory writes; PUC's activation performs 5.
Seven fields (`nextraargs=0`, `lua_packed_flags=0`, `simple_result_dst=0xFF`,
`reg_top`, `tbc_mark`, `tbc_chain_base`, `pending_call_index`) eagerly
initialize state PUC either derives on demand (tbc: global `tbclist`
pointer compare; nextraargs: written only on vararg paths), packs into the
single `callstatus` word, or delegates to the C-stack continuation model.

Mechanism: derive-on-demand where PUC does; pack always-zero fields into
`callstatus` bits (PUC packs nresults + 12 flag bits into ONE u32 write);
make fields valid-only-when-flagged (PUC's `u2` union pattern). Each
removed write is ~1-2 i/it on every call site.

### Combined estimate

#1+#2+#3 ≈ −115..−145 i/it on `lua_calls` (514 → ~370-400) and
−105..−135 on `metamethod_call_noalloc` (622 → ~490-520) — i.e. the whole
shared call-path gap. Note the alloc-family is already at parity
(temp_table_alloc +10.7, string_concat +9.0), so the call path + generic
dispatch are the two remaining structural gaps behind the 1.52x geomean.

### Non-candidates (measured)

- **Metamethod machinery** (TMS lookup, staging, simple_result completion):
  zig +79.8 vs PUC +111.1 — already ahead; do not touch.
- **Out-of-line call overhead**: all fast-path symbols are inlined into the
  73,925-byte `runBytecodeDispatch`; there is no call/return function-call
  overhead left to remove.
- `getTmByObj` at 39.2 i/it for one short-string lookup is ~2x PUC's
  `luaH_Hgetshortstr` estimate, but it is mm-specific and inside a block
  that already nets out cheaper than PUC — deprioritized.

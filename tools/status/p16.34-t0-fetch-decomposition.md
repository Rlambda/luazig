# P16.34 T0 — per-fetch dispatch head decomposition: luazig vs PUC Lua 5.5

Truth-artifact. No production changes. Source: HEAD 3b1ce10 (= 5c16a69 + unit test
only). Engines: `zig build -Doptimize=ReleaseFast` (dispatch symbol
`vm.Vm.runBytecodeDispatch`, 65,332 B, byte-identical to commit-time) and
`make -s lua-c` (PUC 5.5.0, `luaV_execute` @ 0x21340, size 0x3dd1).

Replaces the P16.33 T1 estimate of 16.2 i/fetch (pre-T2/T3) with an exact count:
**zig dispatch head = 18 i/fetch, PUC = 8 i/fetch, gap = 10 i/fetch.**

## 1. Method

- Callgrind n-vs-2n slope (N=20000/40000) on 5 microbench shapes — cancels
  startup + warmup exactly. Harness `/tmp/opencode/t0cg.lua`, analysis
  `/tmp/opencode/t0_slope.py`, raw data `/tmp/opencode/cg-{zig,puc}-<shape>-<N>.out`.
- perf stat `-r 3` aggregates are UNRELIABLE on this hybrid CPU (partial
  counting); single runs match callgrind slopes within 0.5–3% (residual =
  documented hash-seed/GC-timing instruction bimodality, P16.33).
- **Fetch counts measured directly**, not traced: the zig line
  `self.dispatch_pc = ctx.pc` (vm.zig:14247) executes exactly once per fetch —
  its callgrind line count IS the fetch count. PUC fetch counts derived from
  bytecode trace (dump-parity verified: luazig `--dump-bytecode` vs
  `build/lua-c/luac -l -l`, identical opcode sequences; luazig prints 0-based
  jump targets, PUC 1-based) + PUC `donextjump` semantics (see §5).
- Bytecode parity verified before comparing: both engines execute the same
  opcode streams per shape.

## 2. Zig dispatch head (hot backward-edge target 0x10bd210)

All handler tails end `incq -0x98(%rbp); jmp 10bd210`. Verbatim
(`objdump -d`, ReleaseFast):

```asm
10bd210: mov    -0xc8(%rbp),%rsi     ; reload &cur_proto.code   (stack spill)
10bd217: mov    -0x98(%rbp),%rdx     ; reload ctx.pc            (stack spill)
10bd21e: cmp    0x8(%rsi),%rdx       ; pc vs code.len           (len from Proto memory)
10bd222: jae    10bd340              ; exit if pc >= len
10bd228: mov    (%rsi),%rax          ; code.ptr                 (from Proto memory)
10bd22b: mov    (%rax,%rdx,4),%r15d  ; inst = code[pc]          (scaled index)
10bd22f: mov    %rdx,0x620(%r12)     ; self.dispatch_pc = pc    ← PUBLICATION STORE
10bd237: movzbl 0xf94(%r12),%eax     ; self.dispatch_gate       ← GATE LOAD (memory)
10bd240: test   %al,%al
10bd242: je     10bd3d0              ; gate==0 common path
10bd3d0: movzbl %r15b,%eax           ; opcode extract
10bd3d4: and    $0x7f,%eax
10bd3d7: lea    -0xb0e42(%rip),%rcx  ; jump-table base
10bd3de: movslq (%rcx,%rax,4),%rax   ; 32-bit RELATIVE table entry
10bd3e2: add    %rcx,%rax
10bd3e5: jmp    *%rax                ; dispatch
; --- handler tail (example MOVE @10bd3e7) ---
10bd410: incq   -0x98(%rbp)          ; ctx.pc += 1              (memory RMW)
10bd417: jmp    10bd210              ; back edge
```

**Total = 18 i/fetch** (16 head + incq + back-jmp). Confirmed per-line by
callgrind (ann-zig-ia.txt, N=40000, ~80,800 fetches, int_arith):

| vm.zig line | instr/fetch |
|---|---|
| 14231 while-cond (2 stack reloads + len cmp + jae) | 4.00 |
| 14232 fetch (code.ptr load + indexed load) | 2.00 |
| 14247 `self.dispatch_pc = ctx.pc` | 1.00 |
| 14251 gate (byte load + test + je) | 3.00 |
| 14446 `switch (op)` (extract 2 + jump table 4) | 6.00 |
| 16449 default `ctx.pc += 1` (incq) | 1.00 |
| back-jmp (attributed to handler lines) | 1.00 |

Register map: %r12=self(*Vm), %r13=exec_frames, %r15=inst. **pc, &code slice,
regs slice are all STACK-spilled** (-0x98/-0xc8/-0xa8/-0xa0(%rbp)) and reloaded
every fetch / every operand access — the megafunction's register pressure
forces the state out of registers.

## 3. PUC dispatch head (luaV_execute)

Two head clones; hot handlers (MODK, ADDI, EQI, FORLOOP — verified by perf
record on branch_loop, /tmp/opencode/perf-puc-annot.txt) use the
`jmp 215b0 → 213b0` path:

```asm
; --- handler tail: jmp 215b0 ---
215b0: test   %r9d,%r9d              ; trap check (REGISTER-resident local)
215b3: je     213b0                  ; trap==0 common path
213b0: lea    0x4(%r14),%rbx         ; pc advance (pointer bump, register)
213b4: mov    (%r14),%r14d           ; i = *pc   (pc IS a pointer — no bounds check)
213b7: mov    %r14d,%eax
213ba: and    $0x7f,%eax             ; opcode extract
213bd: jmp    *(%r12,%rax,8)         ; dispatch (64-bit ABSOLUTE jump table, 1 load)
```

**Total = 8 i/fetch** (incl. back-jmp). Second clone 21440–21455 (8 instr,
trap check inlined, `add $0x4,%rbx` folding) used by other handlers — same cost.

Register map: %r12=jump-table base, %r13=ci, %rbp=base, %rbx/%r14=pc POINTER,
%r9d=trap. `savedpc` published ONLY at boundaries: `mov %rbx,0x20(%r13)`
appears 44× in luaV_execute, all at call/error/protect sites — **none in the
loop head**. No bounds check anywhere (codegen guarantees terminating RETURN).

## 4. Component comparison (per fetch)

| component | zig | PUC | mechanism difference |
|---|---|---|---|
| loop condition / bounds | 4 | 0 | zig: pc=index, bounds-checked vs code.len re-loaded from Proto memory per fetch, pc+&code reloaded from stack spills. PUC: pc=pointer, no check |
| code[pc] fetch | 2 | 1 | zig: code.ptr re-loaded from Proto + scaled index. PUC: pc is the pointer, single load |
| opcode extraction | 2 | 2 | parity (optimal) |
| dispatch_pc publication | 1 | 0 | zig: real store to Vm+0x620 EVERY fetch (readers: GC safepoints vm.zig:6750/7703/7757, outlined fail). PUC: savedpc only at boundaries |
| gate/trap check | 3 | 2 | zig: byte load from Vm+0xf94 + test + je. PUC: register-resident `trap` local + je |
| switch jump | 4 | 1 | LLVM: 32-bit relative entries (lea+movslq+add+jmp). GCC: 64-bit absolute (jmp *(%r12,%rax,8)) |
| pc advance | 1 | (folded) | zig: incq memory RMW on stack slot. PUC: lea register bump folded into head |
| back-edge | 1 | 1 | parity |
| **TOTAL** | **18** | **8** | **gap 10 i/fetch** |

## 5. Per-workload decomposition (dispatch function)

Fetch counts: zig measured directly (dispatch_pc store count); PUC from
bytecode trace. **Key parity finding:** on a TAKEN conditional jump zig
dispatches the following JMP opcode through the full head (EQI falls through,
vm.zig `.eqi`: `if (result != invert) ctx.pc += 1` — no skip on the taken
side), while PUC's `donextjump` reads the JMP inline and skips it without
dispatching. Hence branch_loop: zig 5.0 fetch/iter vs PUC 4.5.

| shape | z f/it | p f/it | z i/it | p i/it | z i/f | p i/f | gap i/f | head gap i/it | handler gap i/it |
|---|---|---|---|---|---|---|---|---|---|
| int_arith | 2 | 2 | 109.08 | 60.60 | 54.54 | 30.30 | 24.24 | 20 | 28.5 |
| branch_loop | 5 | 4.5 | 233.31 | 140.90 | 46.66 | 31.31 | 15.35 | 50 | ~42 |
| comparisons | 5 | 5 | 245.43 | 154.53 | 49.09 | 30.91 | 18.18 | 50 | 40.9 |
| lua_calls* | 7 | 7 | 481.77 | 207.05 | 68.82 | 29.58 | 39.25 | 70 | 204.7 |
| mm_noalloc* | 5 | 5 | 425.21 | 104.03 | 85.04 | 20.81 | 64.24 | 50 | 171.2 |

\* dispatch-function comparison is apples-to-oranges for call shapes: PUC's
call/metamethod machinery (luaD_precall, luaT_callTMres, luaD_call) is OUTSIDE
luaV_execute; zig's is inside runBytecodeDispatch. Program-level (fair):
lua_calls 485.73 vs 255.53 (gap 230.2 i/it, head 70 → 30%); mm_noalloc 593.94
vs 359.56 (gap 234.4 i/it, head 50 → 21%).

Pure-loop shapes are the clean head comparators: head gap (10 i/fetch ×
fetch/it) explains 41–55% of the dispatch-function instruction gap.

## 6. Verdict: removable components (PUC-first)

| # | component | saving | removable? | how (PUC-parity) |
|---|---|---|---|---|
| 1 | dispatch_pc publication store | −1 i/fetch | **YES, provably** | PUC publishes savedpc only at boundaries. Publish at call boundaries (parkActiveFrame already does), error/yield sites, GC safepoints. Outlined fail readers need pc passed/stored at the error site instead of a per-fetch field |
| 2 | gate memory load → register | −1 i/fetch | **YES** | PUC's `trap` model: register-resident local, refreshed at frame boundaries + backward jumps + C-call returns (updatetrap discipline). debug.sethook granularity = PUC's. Register-pressure risk: P16.0b history (pointer local +3%); a u8 local is exactly what PUC does |
| 3 | bounds check + state reloads + pc-as-index | −4..5 i/fetch | **YES, provably** | pc-as-pointer (PUC model): kills cmp/jae, code.ptr load, pc reload, index scaling; pc advance becomes register lea. Codegen already guarantees terminating RETURN — the per-fetch bounds check is redundant. Largest refactor: ctx.pc is an index across handlers/parkActiveFrame/resume |
| 4 | JMP dispatch on taken condjump | −18 i per taken condjump | **YES** | PUC's donextjump: read jump target inline in the comparison handler, skip the JMP dispatch. branch_loop: −9 i/iter |
| 5 | jump-table format (4 vs 1) | −3 i/fetch | **NO (structural)** | LLVM lowers switch tables as 32-bit relative offsets (movslq+add); no Zig-source control. Manual dispatch would break the megafunction's register-resident ctx |

Already optimal: opcode extraction (2=2), back-edge (1=1).

**Projection** after items 1–4: zig head ≈ 10 i/fetch (0+1+2+0+2+4+0+1).
int_arith: 54.5→44.5 i/fetch → 109→89 i/it (−18% instructions on that shape);
branch_loop additionally −9 i/iter from item 4.

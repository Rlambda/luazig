# P16.34 Cut 2 — dispatch-local gate word (PUC `trap` model): implemented, measured, REJECTED

Cut 2 attempted to remove the per-fetch memory load `self.dispatch_gate`
(T0 component «gate load 1 of 3») by mirroring PUC Lua 5.5's `trap`
ownership model: a dispatch-local `var gate: u8 = self.dispatch_gate;`
initialized at frame_loop entry and refreshed at every boundary where
nested code may have changed hooks — exactly PUC's `updatetrap(ci)` after
every Protect'd call / checkGC, and `trap = luaG_traceexec(...)` at vmfetch.

The implementation was COMPLETE (32 refresh sites, all enumerated below),
all functional gates were GREEN, and the A/B measurement REJECTED it.
This artifact preserves the full analysis so the experiment is not
blindly repeated.

## 1. What was implemented (and reverted)

- `var gate: u8 = self.dispatch_gate;` in the frame_loop body; loop head
  read `gate` instead of the VM field (3 sites: `!= 0`, STATS, HOOKS).
- Refresh `gate = self.dispatch_gate;` after every synchronous nested
  execution returning INTO the inner loop (PUC Protect/updatetrap parity):
  - hooks-block end (PUC `trap = luaG_traceexec` self-correction);
  - index arms after bytecodeGetIndex/bytecodeSetIndex non-pushed returns
    (GETTABUP, SETTABUP, GETTABLE, GETI, GETFIELD ×2, SELF, SETTABLE,
    SETI, SETFIELD);
  - sync metamethod completions: tryPushSimpleResultMetamethod `.value`
    (MMBIN/MMBINI/MMBANK, UNM, BNOT, LEN), slowCmp `.value` (LT, LE,
    LTI, LEI, GTI, GEI), EQ `.value`+`.compare`;
  - unwrap arms `.continue_dispatch`/`.continue_no_advance` of opCall,
    opTailcall, opTforcall, opSetlist;
  - GC-step sites: allocTable (OP_NEWTABLE), condGcFromDispatch
    (OP_CONCAT, OP_CLOSURE) — finalizers are Lua code, PUC refreshes
    trap inside checkGC for exactly this reason.
- NOT refreshed (provably unnecessary): pure register/arith/jump arms;
  OP_CALL inline fast path + opReturn0/1 in-place parent resume (stay in
  the inner loop; fast paths guard on the always-fresh field
  `hooks_active_cached`); STATS (written exactly once by the CLI before
  execution); dojump sites (luazig has NO async gate writer — SIGINT uses
  signal_int_pending, checked separately at backward jumps, P16.10 T8).

Mutation inventory (why the refresh list is complete): the only HOOKS-bit
writers are refreshHooksCached, called from builtinDebugSethook
(debug.sethook — always a callee), lua_sethook (C API — from builtins or
hook callbacks), and switchRuntime (coroutine switches — inside
resume/yield builtins). Every writer is synchronous and nested; every
return path crosses a refresh site or a frame boundary.

## 3. Root cause: LLVM re-materialization + back-edge threading

Disassembly (runBytecodeDispatch, ReleaseFast):

- The loop head STILL loaded the field per fetch:
  `movzbl 0xf8c(%r15),%r13d` — LLVM legally re-materialized the local as
  a memory load: on pure-arm paths no write to the field occurs, so
  `gate == self.dispatch_gate` is provable, and a reload is cheaper than
  keeping a byte register live across a ~400 KB switch. The local never
  became register-resident — the T0 premise («1 removable load per
  fetch») is NOT realizable this way.
- The 32 refresh sites created a loop-carried phi for `gate`; LLVM
  jump-threaded the loop and DUPLICATED the back-edge into a new block
  (0x10ca580 in the after build): `movzbl gate; incq pc; mov rsi; mov
  rdx; cmp; jb` → jumps PAST the head's gate load. Edges routed through
  the duplicated block pay +2 i/fetch vs the single head (extra gate
  reload + `xor %r13d,%r13d` phi materialization on the gate==0 path).
  comparisons and lua_calls route ~2 fetches/iter through it: +4 i/iter.
- The whole-function recompilation shifted code layout: hash_access lost
  ~12% wall time with byte-identical dynamic instruction counts
  (callgrind-verified) — branch-predictor / cache-line / alignment class
  of effect, the same «bimodal-noise» family documented in P16.33 T3, but
  deterministic and reproducible 5/5.

PUC comparison: GCC keeps `trap` register-resident (%r9d per T0) across
lvm.c's switch because PUC's switch is one function with ~10 refresh
sites and far lower register pressure. LLVM on our 400 KB switch makes
the opposite (legitimate) RA choice. Forcing residency would require
either shrinking the dispatch function or non-portable register pinning —
out of scope for this cut.

## 4. Verdict and what was KEPT

REJECTED: the gate-local + 32 refresh sites reverted (head reads
`self.dispatch_gate` again; a tombstone comment at the head documents the
rejection and points here).

KEPT (this is the committed content of Cut 2):

1. **switchRuntime exit-ordering parity fix** (found by probe 6, pre-existing
   bug at Cut 1 HEAD): `builtinCoroutineResume` and the coroutine-close
   path restored `current_thread` AFTER `switchRuntime` in their exit
   defers, so `refreshHooksCached` (inside switchRuntime) read the
   COROUTINE's hook state on the way out — a coroutine clearing its own
   hook silenced a still-installed MAIN hook after resume returned
   (missing line events for the remainder of the frame). Fix: restore
   `current_thread` BEFORE `switchRuntime` (the entry path already had
   the correct order; the trampoline bubble path was also correct).
2. **tests/smoke/74_hook_trap_state.lua** — 10-probe hook-visibility
   parity gate (PUC-captured, byte-identical both engines):
   install-from-nested-call, clear-from-inside-hook, line→count mask
   switch mid-frame, count-hook semantics (COUNT enabled by 4th arg
   independent of mask; absolute firing counts are compiler-dependent —
   our instruction streams are more compact than PUC's — so the probe
   asserts semantics, not counts), call/return ordering, per-thread
   hooks across yield/resume (the probe-6 scenario), sethook on a
   suspended coroutine then resume, install + sync string __add (MMBIN),
   install + sync builtin __index (rawget), install from inside a
   metamethod body.

## 6. Follow-ups (backlog)

- The T0 «gate load» component stays open: any future attempt must
  either shrink the dispatch function (split cold arms out — would also
  help I-cache) or accept the field read as the PUC-parity shape (PUC's
  vmfetch also reads a per-fetch branch condition; the LOAD itself is
  L1-resident and fused).
- Measurement hygiene: gate tools that rebuild (api580_gate.py builds
  Debug then ReleaseFast into zig-out) can silently invalidate A/B
  binaries — always verify saved A/B binaries by a behavior marker.

# P16.35 cursor audit — inventory of every `ctx.pc` site (2026-09-10)

Scope decision for the next dispatch-head component. T0 (fetch decomposition,
`p16.34-t0-fetch-decomposition.md`) verdict: **pc-as-pointer cursor win,
re-measured below as −2..−3 i/fetch (provably)** — PUC's `savedpc` is an
`Instruction*` cursor, our `ctx.pc` is a `usize` index, so every fetch pays
`code.ptr` re-read from the Proto + two spill reloads, and every advance
pays a stack-RMW `incq` where PUC folds the advance into the next fetch.
(The original T0 figure of −4..−5 double-counted the scaled-index
addressing mode and the advance fold — see the component table.) Cut 3
removed the bounds condition (T3.1, 6290951); the cursor conversion (T3.2,
scaled down to P16.35) is the remaining provable head component besides
the rejected gate-local (Cut 2) and the structural jump-table cost.

This audit inventories every `ctx.pc` use to size the conversion.

## Method

`grep ctx.pc` over `src/lua/vm.zig` at 6290951: 207 raw matches, **182 code
uses** (25 are comments). Split into the dispatch-loop region (14269–16636,
**143 uses**) and the rest (**39 uses**).

**MMBIN-skip family dominates**: the arith/bitwise handlers account for
~70 of 143 uses (35 explicit skips + their paired plain advances) — every
ADD/SUB/MUL/…/BAND/… pays two advances (skip MMBIN + loop tail). PUC parity
note: PUC 5.5 OP_ADD also does `pc++` to skip its MMBIN follower — the
double-advance is PUC-faithful; only the *representation* (index vs pointer)
differs.

## Conversion decisions to make (P16.35 planning)

1. **Invariant**: keep "pc points AT the current instruction" (representation
   change only, all 182 sites mechanical) vs adopt PUC's "savedpc points
   PAST the current instruction" (semantic shift — every handler's view of
   `pc` changes; full PUC parity but a much larger, error-prone diff).
   Recommendation: representation change first (index → `[*]const
   Instruction` cursor or slice iterator), measure; PUC-invariant shift only
   if the representation change alone doesn't capture the T0 projection.
2. **Heap CallFrame field** (`u.lua.pc: usize` — 8 B at u.lua offset 8,
   per `src/lua/vm.zig` LuaFrameState and
   `tools/perf/current-callframe-layout.json`; an earlier revision of this
   audit wrongly called it `u32`): PUC stores a pointer (`savedpc`).
   Options: keep the index (publish = `cur - code.ptr`, one sub at each
   publish site — cold paths, wall-neutral) or change the field to a
   cursor (touches C API surface that reads frame pc). Keeping the index
   is the low-risk PUC-divergence-with-justification: the published value
   is read back by our own restore sites, the GC live-reg scan, hook
   replay state, and debug/error attribution (full reader inventory in
   the heap-PC section below) — all cold or boundary paths that already
   pay an index→data conversion for `lineinfo`/`live_reg_top` lookups.
3. **Fail-site signatures** (9 in-loop + cold paths): pass the cursor or the
   derived index; error location math (`pc - 1` for MMBIN attribution) must
   be preserved exactly (73_error_location_pc.lua covers it).
4. **SIGINT backward-jump poll** and `dispatchDoNextJump` arithmetic stay
   index-free: cursor deltas are instruction counts, same values.

### 4. Conversions between ctx.pc and heap pc

- **Publish ctx→heap** (~22 sites, all boundary/cold): plain store, both
  `usize` — no arithmetic today. A cursor representation adds exactly one
  `cur - code.ptr` sub per site (cold, wall-neutral).
- **Restore heap→ctx** (8 sites): plain load. Inverse of publish.
- **Narrowing to compact u32 fields** (~18 sites): `@intCast(pc)` into
  resume_pc/last_line_pc/skip_* (see below) and
  `@intCast(@min(pc, maxInt(u32)))` in debug/c_api (u32 clamping for
  locvar-range math). A cursor representation derives the index once at
  these cold sites (`cur - code.ptr`), same cost class.

## Dispatch-head decomposition, re-measured on THIS source (T0.3)

Fresh objdump at HEAD 016532d (src/ == 6290951), binary
`zig-out/bin/luazig` ReleaseFast, `nm -S`:
`vm.Vm.runBytecodeDispatch` = 0x10bce30, size 0x10900. Dominant
backward-edge target (73 edges): **0x10bd125**; loop-tail `incq` at
0x10bd11e (61 direct edges). Verbatim sequential-path sequence:

```asm
; ── fetch ──
10bd125: mov    -0xc0(%rbp),%rsi    ; 1  reload ctx.cur_proto (spill slot)
10bd12c: mov    -0x90(%rbp),%rdx    ; 2  reload ctx.pc (spill slot)
10bd133: mov    (%rsi),%rax         ; 3  load code.ptr from Proto
10bd136: mov    (%rax,%rdx,4),%ebx  ; 4  load instruction (scaled index ×4)
; ── gate ──
10bd139: movzbl 0xf8c(%r13),%eax    ; 5  gate word load (VM field — NOT a local;
                                     ;    Cut 2's rejection evidence, still true)
10bd141: test   %al,%al             ; 6  gate test
10bd143: je     10bd250             ; 7  gate branch (not-taken → dispatch)
; ── dispatch table (10bd250) ──
10bd250: movzbl %bl,%eax            ; 8  opcode zext
10bd253: and    $0x7f,%eax          ; 9  7-bit opcode mask
10bd256: lea    table(%rip),%rcx    ; 10 table base
10bd25d: movslq (%rcx,%rax,4),%rax  ; 11 4-byte offset load (scaled)
10bd261: add    %rcx,%rax           ; 12 target = base + offset
10bd264: jmp    *%rax               ; 13 indirect jump
; ── handler body (e.g. MOVE: 5 instr, 10bd266–10bd286) ──
; ── loop tail ──
10bd28b: incq   -0x90(%rbp)         ; 14 ctx.pc += 1 — STACK RMW on the spill
10bd292: jmp    10bd125             ; 15 back-branch
```

**Zig head = 15 i/fetch** on the sequential path (fetch 4 + gate 3 +
dispatch 6 + tail 2) — matches the realized ~15 reported at P16.34
close, not the ~10 projected from T0.

PUC reference (`build/lua-c/lua`, `luaV_execute` = 0x21340, dominant
head 0x21440 with 35 backward edges; duplicate 0x215b0→0x213b0 with 26):

```asm
; ── trap gate ──
21440: test   %r9d,%r9d            ; 1  trapcount check (register-held)
21443: jne    214a0                ; 2  → luaG_traceexec (call path)
; ── fetch (savedpc cursor, register-held) ──
21445: mov    %rbx,%rax            ; 3  current cursor (already advanced)
21448: add    $0x4,%rbx            ; 4  advance folded into NEXT fetch
2144c: mov    (%rax),%r14d         ; 5  instruction load — unscaled, no code.ptr re-read
; ── dispatch ──
2144f: mov    %r14d,%eax           ; 6  copy for extract
21452: and    $0x7f,%eax           ; 7  opcode mask
21455: jmp    *(%r12,%rax,8)       ; 8  dispatch — 8-byte absolute entries, ONE instr
```

**PUC head = 8 i/fetch** for the 0x21440 variant (trap gate 2 + fetch 3 +
extract/dispatch 3); the 0x215b0→0x213b0 variant is 7 (`lea`-fold, no
cursor copy). Handler tails add one explicit back-jump (`jmp 21440` ×19
sites / `jmp 215b0` ×25 sites in luaV_execute), so the fair
sequential-path totals are **PUC 8–9 vs Zig 15**. PUC publishes
`savedpc` to the frame only at boundaries (`mov %rbx,0x20(%r13)` before
calls — 21412, 22067), the exact model our Cut 1 adopted.

### Component table (fresh, disasm-verified — corrects the stale T0 estimate)

| component (sequential path) | Zig (i) | PUC (i) | cursor conversion effect |
|---|---|---|---|
| fetch + advance | 5 (cur_proto spill reload, pc spill reload, code.ptr load, scaled inst load, tail `incq` RMW) | 2–3 (`lea/add` advance folded + unscaled load [+ cursor copy]) | **−2..−3**: the four Zig fetch instructions collapse into 2–3 PUC-shaped ones; the tail incq disappears into the fold |
| gate | 3 (VM-field load + test + je) | 2 (register test + jne) | 0 — Cut 2 proved the gate load is NOT localizable (LLVM re-materializes a local as this very `movzbl 0xf8c(%r13)`) |
| opcode extract | 2 (movzbl + and) | 2 (mov + and) | 0 |
| dispatch table | 4 (lea + movslq + add + jmp*) | 1 (jmp *(,8), 8-byte absolute entries) | 0 — structural jump-table cost, not pc-related |
| back-branch | 1 | 1 | 0 |
| **total** | **15** | **8–9** | **−2..−3 provable** |

**Correction of the stale T0 estimate (−4..−5 i/fetch)**: it
double-counted. The "index→address computation" costs **zero**
instructions — the ×4 scale is an addressing mode inside
`mov (%rax,%rdx,4)`, not a separate instruction — and the advance-fold
win is not additive on top of the fetch-side wins (PUC's fold IS the
fetch-side win). The honest provable component is the whole
fetch+advance block: 5 Zig instructions → 2–3 PUC-shaped ones =
**−2..−3 i/fetch**, bounded above by cursor register residency (best
case, PUC's rbx) and below by a spilled cursor (worst case: reload +
load + RMW addq ≈ 3). Of the remaining 6–7 gap, the gate load (1) is
proven unfixable (Cut 2) and the 4-vs-1 jump-table sequence (3) is
structural — neither is touched by the cursor. Re-measure with A/B
instructions:u + callgrind remains mandatory before accepting any
conversion (Cut 2 lesson: LLVM can refuse register residency and
re-materialize).

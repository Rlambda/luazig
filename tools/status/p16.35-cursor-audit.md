# P16.35 cursor audit — inventory of every `ctx.pc` site (2026-09-10)

Scope decision for the next dispatch-head component. T0 (fetch decomposition,
`p16.34-t0-fetch-decomposition.md`) verdict: **pc-as-pointer cursor −4..5
i/fetch (provably)** — PUC's `savedpc` is an `Instruction*` cursor, our
`ctx.pc` is a `usize` index, so every fetch pays `code.ptr` re-read from the
Proto + index→address computation, and every advance pays a stack-RMW `incq`
where PUC folds the lea into the next fetch. Cut 3 removed the bounds
condition (T3.1, 6290951); the cursor conversion (T3.2, scaled down to
P16.35) is the remaining provable head component besides the rejected
gate-local (Cut 2) and the structural jump-table cost.

This audit inventories every `ctx.pc` use to size the conversion.

## Method

`grep ctx.pc` over `src/lua/vm.zig` at 6290951: 207 raw matches, **182 code
uses** (25 are comments). Split into the dispatch-loop region (14269–16636,
**143 uses**) and the rest (**39 uses**).

**MMBIN-skip family dominates**: the arith/bitwise handlers account for
~70 of 143 uses (35 explicit skips + their paired plain advances) — every
ADD/SUB/MUL/…/BAND/… pays two advances (skip MMBIN + loop tail). PUC parity
note: PUC 5.5 OP_ADD also does `pc++` to skip its MMBIN follower — the
double-advance is PUC-faithful; only the *representation* (index vs pointer)
differs.

## Conversion decisions to make (P16.35 planning)

1. **Invariant**: keep "pc points AT the current instruction" (representation
   change only, all 182 sites mechanical) vs adopt PUC's "savedpc points
   PAST the current instruction" (semantic shift — every handler's view of
   `pc` changes; full PUC parity but a much larger, error-prone diff).
   Recommendation: representation change first (index → `[*]const
   Instruction` cursor or slice iterator), measure; PUC-invariant shift only
   if the representation change alone doesn't capture the T0 projection.
2. **Heap CallFrame field** (`u.lua.pc: u32` today): PUC stores a pointer
   (`savedpc`). Options: keep the index (publish = `cur - code.ptr`, one sub
   at each of the 10 publish sites — cold paths, wall-neutral) or change the
   field to a cursor (touches C API surface that reads frame pc). Keeping
   the index is the low-risk PUC-divergence-with-justification: the published
   value is only read back by our own restore sites and error reporting.
3. **Fail-site signatures** (9 in-loop + cold paths): pass the cursor or the
   derived index; error location math (`pc - 1` for MMBIN attribution) must
   be preserved exactly (73_error_location_pc.lua covers it).
4. **SIGINT backward-jump poll** and `dispatchDoNextJump` arithmetic stay
   index-free: cursor deltas are instruction counts, same values.

## Projection (from T0)

Head today ≈ 14 i/fetch after Cut 1+3 (18 − 1 publication − 1 gate-word
attempt failed − 4 bounds/spill removed in T3.1... measured −3..−5%
instructions uniformly, consistent with the 4-i component). Cursor removes
the fetch-side `code.ptr` reload + address computation and folds the
pc-advance: T0 estimate −4..5 i/fetch on fetch-heavy workloads
(int_arith/head-dominated). Must re-measure — Cut 2's lesson: LLVM layout
responses can eat projected wins; A/B instructions:u + callgrind per-line
attribution mandatory before accepting.

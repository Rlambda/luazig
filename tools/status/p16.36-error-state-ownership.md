## 1. The fundamental ownership divergence (PUC vs luazig)

PUC keeps **all error identity on the raising thread's stack**:

- the error OBJECT is a stack value (`L->top-1`; `luaD_seterrorobj` ldo.c:112
  moves it to the recovery `oldtop`; `luaG_errormsg` ldebug.c:840 hands it to
  the handler);
- the status code (`LUA_ERRERR` etc.) travels **per-thread** through
  `L->errorJmp->status` / `L->status` (`luaD_throw` ldo.c:125, `luaD_errerr`
  ldo.c:215);
- `L->errfunc` (lstate.h:301) and `L->status` (lstate.h:288) are lua_State
  (per-thread) fields;
- there is **no global error message buffer, no global traceback, no label
  state** — messages are immutable TStrings, tracebacks are built by handlers
  at throw time from live frames, and C frames are real CallInfos that appear
  in traceback walks.

luazig instead funnels the error channel through **Vm-global fields** and
compensates with a **save/restore ceremony at every protected/coroutine
boundary**. The entire ceremony family (7–10 field bundles, byte copies,
transfer-ownership of `err_traceback`) exists only because the channel lives
on the Vm. This is also perf mechanism #1 of the p16.35-t5 coroutine
decomposition (resume-side state ceremony ~380 i/it).

## 2. Vm error fields — inventory

Counts: R = reader sites, W = writer sites in vm.zig (grep-classified; ±2
accuracy on multi-statement lines).

### 2.1 `Vm.err` (?[]const u8, R34/W46) — **SCRATCH (alias), hazard**
- **Alias target**: EITHER `err_buf[0..len]` (fail/failRunerror/failC/failLib
  and error()/assert() prefix paths write via `bufPrint(self.err_buf...)`) OR
  an interned LuaString's bytes (error(msg,0)/assert no-prefix paths:
  `self.err = msg`; invokeErrfunc handler-result path; restoreRuntimeErrorValue
  re-points it at the snapshot string).
- **Readers**: `errorString()` (6374), `protectedErrorString()` (7309, renders
  into `err_render_buf`), `formatCliError` fallback (6464), resume !ok tail
  fallback (22494/22501), trampoline/clsret re-materialization via
  `currentRuntimeErrorValue` (8244→7309), c_api error windows.
- **Lifetime**: valid only until the next raise on ANY thread (Vm-global).
- **Across coroutine switch**: saved as a SLICE by builtinCoroutineResume
  (21755) — **no byte copy**. If the coroutine raised a formatted error, the
  restored slice points into `err_buf` whose bytes the coroutine overwrote
  (stale-bytes alias). Same slice-only save in builtinPcall (20720) /
  builtinXpcall (21054) / debug-runner (29691).
- **PUC analogue**: none (messages are immutable TStrings).
- **Proposed owner**: Vm scratch is acceptable ONLY if no semantic path reads
  it across a boundary; today `currentRuntimeErrorValue`/`protectedErrorString`
  do. PUC-first fix: bake the prefix at raise (already done for `err_obj`) and
  make every boundary consumer read `err_obj` (interned, immutable) — then
  `err` becomes pure rendering scratch. Hot-path impact: none (all readers are
  cold error paths).

### 2.2 `Vm.err_obj` (Value, R37/W47) — **SEMANTIC**
- The error OBJECT (PUC: stack value at `L->top-1` of the raising thread).
  Interned at raise in every fail-family path → bytes immutable.
- **Across switch**: saved/restored by all bundles (resume 21756, pcall 20721,
  xpcall 21055, BytecodeSavedError 8084, closeThreadProtected 22667).
- **PUC analogue**: per-thread stack slot. **Proposed owner**: Thread (with the
  whole channel, §7). Hot-path impact of moving: removes 3 saves/restores from
  the resume ceremony; readers are boundary-cold.

### 2.3 `Vm.err_has_obj` (bool, R31/W42) — **SEMANTIC**
- Companion validity flag (PUC has no analogue: an object is always on the
  stack; `error(nil)` pushes nil and luaG_errormsg normalizes to
  "<no error object>" only for the protected RESULT).
- Saved/restored everywhere err_obj is. Proposed owner: Thread (with err_obj).

### 2.4 `Vm.err_cframe_residue` (?Value, R7/W13) — **SEMANTIC**
- P15.83q: transcription of the `orig` slot error()/assert() leave below the
  built message on their C-frame; exposed by c_api lua_resume as the leading
  slot of the error window (`[residue?, err, err]`, ldo.c:112 dup parity).
- Writers: error() (19389), assert() (20284/20291/20296), cleared at fresh
  raises (19338, 20256), saved/restored at pcall (20737/21067), resume
  (21759/21773), close (22669/22709), debug-runner (29716/29734); snapshotted
  onto the dying thread as `Thread.api_err_residue` at resume's !ok tail
  (22506) because the c_api reads it AFTER the caller's channel is restored.
- **NOT in BytecodeSavedError** (yield-across-pcall continuation): a parked
  caller's residue is dropped at that boundary (latent, window-shape only).
- **PUC analogue**: the real stack slots (per-thread, naturally isolated).
- **Proposed owner**: Thread (with the channel).

### 2.5 `Vm.err_is_errerr` (bool, R6/W10) — **SEMANTIC, LEAKS across switch**
- PUC LUA_ERRERR signal: set by `raiseErrerr` (7097), reset at every fresh
  raise (6708/6734/6801/6825, error() 19335, c_api 396, 41463), read at
  status-determination sites: pcallk recovery `setcistrecst` (11069/11084),
  clsret error-escape restore (11235), resume !ok tail + running-escape defer
  (21749, 22499), api.State.pcall status (api.zig:808), c_api lua_resume
  (c_api.zig:1858/2074/2171), apiCloseConventionalPcallBoundary (37957).
- **NOT saved by builtinCoroutineResume, builtinPcall, builtinXpcall, or
  BytecodeSavedError** — only closeThreadProtected saves it (22670/22710).
  → a coroutine's ERRERR (its handler recursion exhausted) leaks into the
  caller's subsequent status reads; conversely the caller's pending ERRERR
  can be masked by any fresh raise inside a resumed coroutine (TBC closer
  during the errerr's own unwind).
- **Observability**: status codes only (C-API surfaces: lua_resume return,
  api.State.pcall status, setcistrecst). No pure-Lua reproducer found — T2.2
  probes show Lua-level parity. Latent divergence, statically proven.
- **PUC analogue**: the errcode traveling per-thread (errorJmp->status).
- **Proposed owner**: Thread.

### 2.6 `Vm.err_source` (?[]const u8, R10/W33) / 2.7 `Vm.err_line` (i64, R12/W33) — **SEMANTIC (divergent bookkeeping)**
- Kept separately from the message so `protectedErrorString` can re-render
  "chunk:line: msg" at boundary crossings (`currentRuntimeErrorValue`
  8244, CLI handler 6420, formatCliError 6475). PUC has **no such state**:
  `luaG_addinfo` bakes the prefix into the TString at raise (ldebug.c:830-840)
  and nobody re-renders. luazig therefore carries TWO representations of the
  same message (baked `err_obj` + re-renderable `err`/`err_source`/`err_line`)
  — the reason `protectedErrorString` exists at all.
- Cleared by invokeErrfunc on handler success (7125-7129: the handler's result
  must not get the position re-applied — PUC parity) and by
  restoreRuntimeErrorValue (8262).
- Saved/restored by all bundles. **Proposed owner**: Thread (with the channel);
  longer-term PUC-first: bake-at-raise only, delete the re-render path.

### 2.8 `Vm.err_traceback` (?[]u8, R12/W19) — **SEMANTIC, transfer-ownership**
- Heap buffer captured at fault point by `captureErrorTraceback` (6586) —
  reads `err_cfunc_label` (§2.10) to synthesize the top C frame. No PUC
  analogue in state (PUC handlers build tracebacks from live frames).
- **Ownership protocol**: the pointer is TRANSFERRED at every boundary —
  savers park the caller's pointer in the bundle and null the Vm field
  (21763, 8098, 20725, 21058, 22675); the boundary that ends an error frees
  the current one (`clearErrorTraceback` 6576) before restoring the parked
  one; `discardBytecodeSavedError` (8123) frees a parked caller's traceback
  when the caller itself is unwound/collected. Every saver must remember this
  or double-free / leak.
- **Proposed owner**: Thread.

### 2.9 `Vm.err_buf` ([2048]u8, R17/W0-as-field) / `Vm.err_render_buf` ([512]u8, R3) — **SCRATCH**
- `err_buf`: the raise-side formatting buffer (fail family, error()/assert
  prefix paths). Shared by ALL threads (Vm-global) — the alias hazard of §2.1.
  Note two truncations live here: error()/assert() prefix path truncates the
  user message at 256 (`msg_tmp` 19403/20273); BytecodeSavedError truncates
  the parked message at 256 on save (8090). PUC has no truncation (messages
  are heap TStrings) — latent divergence for >256-byte messages.
- `err_render_buf`: protectedErrorString's render target (7321/7330/7335).
  Returned immediately; a nested render between render-and-use would clobber
  (no current path does — invokeErrfunc's handler-result path re-derives err).
- **Proposed owner**: stay Vm scratch (rendering is single-threaded at any
  instant — switchRuntime serializes threads).

### 2.10 `Vm.err_cfunc_label` (?[]const u8, R3/W8) — **SEMANTIC, LEAKS across switch — T2.3 DIVERGENCE (confirmed)**
- Synthetic substitute for PUC's real C CallInfo in tracebacks: when non-null,
  `captureErrorTraceback` (6598-6601) inserts `\t[C]: in {label}` at the top.
- Setters: error() → "global 'error'" (19428), assert() → "global 'assert'"
  (20268), yield-non-yieldable → "field 'yield'" (21422), c_api error (42676);
  cleared by fail (6712), failRunerror (6743), failLib (6831); **preserved by
  failC** (6806-6808 comment: "may have been set by the caller — preserve it").
- **NOT saved by resume/pcall/xpcall/BytecodeSavedError** — only
  closeThreadProtected (22674/22714).
- **Two confirmed divergences** (T2.3, verbatim captures below):
  1. failC call sites that never preset a label (xpcall bad-arg 20953/20956,
     io.open, string.format, …) produce a traceback with NO `[C]` frame where
     PUC shows `[C]: in global 'xpcall'` / `[C]: in field 'open'`.
  2. A stale label from ANY recovered error — same-thread via pcall, or
     CROSS-THREAD via coroutine.resume — is mis-attributed: the next
     failC-without-preset shows `[C]: in global 'error'` (or 'assert') for an
     unrelated xpcall/io.open error.
- **PUC analogue**: the C function's CallInfo on the stack (structural, no
  state). **PUC-first fix direction** (for a later cut): derive the synthetic
  frame structurally at capture time from the top hidden builtin C-frame
  (builtins DO push hidden C-frames; invokeErrfunc already unhides the top one
  structurally at 6999-7012) — deleting the label state entirely; interim:
  preset the label at every failC/failLib site + add the field to all bundles.
- Hot-path impact of any fix: zero (all error-path/cold).

### 2.11 `Vm.in_error_handler` (usize, R1/W2) — **COUNTER (window-scoped)**
- `invokeErrfunc` += 1 around the handler window (7017/7018); read by
  `activeErrorHandlerDepth` (5147-5151) to grant ERRORSTACKSIZE headroom in
  pushBytecodeExecFrame (PUC ldo.c:351-357 parity: "stack larger than maximum
  ⇒ thread is handling a stack error").
- Correctly NOT saved across resume: the handler window is live across the
  switch (a resume inside a handler is still inside the handler); the defer
  pairing in invokeErrfunc owns the decrement. **PUC analogue**: structural
  (stack size > MAXSTACK). Keep as-is.

### 2.12 `Vm.protected_call_depth` (usize, R2/W8) — **COUNTER**
- +=/-= around builtinPcall (20644), builtinXpcall (21028), resume (21689);
  read by activeProtectedCallDepth (5141, summed with the active thread's
  bytecode_protected_depth) and the resume-invariant check (12173).
- PUC analogue: the C-stack nesting of luaD_rawrunprotected (structural).
  Correctly not saved across resume (scoped to the resume itself). Keep.

## 4. Machinery inventory

### 4.1 `BytecodeSavedError` (837-857) — why it copies bytes
Fields: err_present, err_len, **err_bytes[256]**, err_obj, err_has_obj,
err_source, err_line, err_traceback (transfer), errfunc.
The byte copy exists **because `self.err` aliases the Vm-global `err_buf`**
which the protected child can overwrite — the copy is the workaround for the
shared buffer (same evidence as closeThreadProtected's 2048-byte copy,
22657-22666: "self.err always aliases self.err_buf[0..len] … so the byte range
is the exact save format"). `restoreBytecodeSavedError` (8105) memcpy's the
bytes back into err_buf. **Missing from the snapshot**: err_cframe_residue,
err_is_errerr, err_cfunc_label; **err_len caps at 256** → a parked caller
message >256 B is truncated on restore (latent divergence; require's long
messages).

### 4.2 fail family
- `fail` (6732, luaG_runerror): reset errerr; clear label; msg → err_buf;
  err = slice; err_source/err_line from topLuaFrame; **err_obj = interned
  "chunk:line: msg"** (bake-at-raise, PUC luaG_addinfo parity); captureErrorTraceback;
  invokeErrfunc.
- `failRunerror` (6699): top-frame dispatch — Lua frame ⇒ fail(); C frame ⇒
  bare message, label cleared, no source.
- `failC` (6799): C-variant — **preserves the existing err_cfunc_label**
  (the T2.3 bug vector), no source, err_obj interned bare.
- `failLib` (6823, luaL_error): like failC but clears the label.
- `raiseErrerr` (7096, luaD_errerr): err_is_errerr=true, fixed object,
  clearErrorTraceback, NO handler re-run.
- `setOutOfMemoryError` (7108): "not enough memory" (LUA_ERRMEM analogue;
  PUC reuses the preallocated `g->memerrmsg`).
- `error()` builtin (19334-19437): reset errerr+residue; level≥1 string ⇒
  prefix bufPrint into err_buf (user msg truncated at 256), residue = original
  arg, label "global 'error'"; level 0 / non-string ⇒ err = LuaString bytes /
  null, err_obj = arg as-is.
- `assert` (20254+): same shape, label "global 'assert'".

### 4.3 `clearErrorTraceback` (6576) / `captureErrorTraceback` (6586)
Free/capture pair implementing the err_traceback transfer-ownership protocol
(§2.8). captureErrorTraceback reads err_cfunc_label (§2.10 leak vector) and
walks Thread.call_frames most-recent-first, retaining both ends of deep
tracebacks (PUC luaL_traceback BUCKET parity).

### 4.4 `invokeErrfunc` (6978, luaG_errormsg)
Retry-loop re-entrancy model (errfunc_running_idx guard); unhides the raiser's
top C-frame for the handler window (structural, 6999-7012); in_error_handler
headroom; ≤256 retries then emergency "C stack overflow" object; handler
success ⇒ err_obj = result (nil → "<no error object>"), err = result bytes,
**err_source/err_line cleared** (position not re-applied — PUC parity);
handler error ⇒ retry with the new raw object; emergency failure ⇒ raiseErrerr.

### 4.5 Protected-call snapshots
`BytecodeProtectedCall`/`Layer` (855-883): saved_error (BytecodeSavedError),
saved_ncalls (nCcalls at entry — the iterative-unwind recovery restores the
thread depth here, PUC gets it from the C-stack unwind), armed_errfunc,
tbc_chain_base (PUC old_top), outer_layers. `finishBytecodeProtectedCall`
(8145): pop armed errfunc slot, restore nCcalls, restoreBytecodeSavedError per
layer, shrinkBcStack. `discardBytecodeProtectedCall` (8174): unwind/collect
path — current error stays authoritative, parked layers freed.

### 4.6 `builtinCoroutineResume` save/restore bundle (21755-21777) — EXACT list
**Saves (7)**: err (slice only — NO byte copy), err_obj, err_has_obj,
err_cframe_residue, err_source, err_line, err_traceback (transfer: caller's
parked, field nulled at entry, current freed at exit).
**MISSES (3 + alias)**: **err_is_errerr**, **err_cfunc_label** (both confirmed
leak vectors — §2.5, §2.10), **err_buf bytes** (the §2.1 alias hazard —
dynamically masked, see T2.4), plus in_error_handler/protected_call_depth
(correctly not saved — window/entry-scoped).
Also saves/restores: th_resume.errfunc (cleared for the coroutine, PUC
lua_resume parity), protected_call_depth += 1, current/prev thread status,
and snapshots err_cframe_residue → th.api_err_residue at the !ok tail (22506)
for the c_api window.

### 4.7 c_api `lua_resume` path (c_api.zig ~1840-1900)
Error window = `[api_err_residue?, err, err]` (luaD_seterrorobj dup parity);
object from vm.err_obj (interned — safe); status from `co.api_status == 5`
(c_api.zig:1891) or, on the dead-before-call path, **vm.err_is_errerr read
AFTER the engine call returned** (c_api.zig:1858) — a VM-global read of
post-restore state (edge: only wrong if the caller had a pending ERRERR,
which requires an errerr in flight across a C-API resume — no known path).

### 4.8 `coroutine.close` error transfer — `closeThreadProtected` (22630+)
The **ONLY complete saver**: all 10 fields (err bytes **full 2048 copy**,
err_obj, err_has_obj, err_cframe_residue, **err_is_errerr**,
err_source, err_line, err_traceback, **err_cfunc_label**) + runtime context
(current_thread, prev status, active_runtime_thread, cur_handle, cur_c_stack,
caller). Evidence the full field set was already identified for close — the
resume/pcall bundles are missing subsets of it. Error transfer: closers'
errors travel via closeTbcRegion's return value (last-error-wins,
luaD_closeprotected parity), not via the channel.

## 5. Semantic vs scratch — classification summary

| class | fields | verdict |
|---|---|---|
| SEMANTIC (error identity; must be per-thread) | err_obj, err_has_obj, err_cframe_residue, err_is_errerr, err_source, err_line, err_traceback, err_cfunc_label | all Vm-global today; err_is_errerr + err_cfunc_label PROVEN to leak across switches; proposed owner: Thread |
| SCRATCH (rendering/workspace) | err (alias), err_buf, err_render_buf | Vm scratch is safe ONLY if no boundary consumer reads `err`; today currentRuntimeErrorValue/protectedErrorString do (masked by interning + snapshots) |
| COUNTERS (machinery depth) | in_error_handler, protected_call_depth, protected_c_frame_depths/count, Thread.bytecode_protected_depth | balanced by construction; correctly not saved |
| PER-THREAD CORRECT already | Thread.api_status, errfunc, errfunc_running_idx, err_traceback | PUC-parity homes; no action |

## 6. Proposed owner (PUC-first direction, for a later cut)

Move the SEMANTIC channel (§5 row 1) onto **Thread** — `switchRuntime` swaps
it with bc_stack/bc_boxed exactly like the existing buffer swap. This:
1. deletes the entire save/restore bundle family (resume 7-field bundle,
   pcall/xpcall bundles, BytecodeSavedError's byte copy + 256-truncation,
   closeThreadProtected's 2048 copy) — the bundles exist only because the
   channel is Vm-global;
2. closes both leak vectors by construction (err_is_errerr, err_cfunc_label
   become per-thread);
3. removes ~10 field saves/restores from the resume transition — part of the
   measured ~380 i/it resume ceremony (p16.35-t5 mechanism #1);
4. keeps err_buf/err_render_buf as Vm scratch (rendering is serialized by
   switchRuntime).
err_cfunc_label additionally has a state-free PUC-first alternative: derive
the synthetic C frame from the top hidden builtin C-frame at capture time
(§2.10), deleting the field.

## 7. T2 differential probes (both engines, verbatim)

### T2.1 nested resume from message handler — PARITY
`/tmp/opencode/p36_t21.lua`: outer xpcall handler resumes an erroring inner
coroutine. Both engines: `xpcall: false H: m=outer-err iok=false ierr=inner-err`;
later pcalls clean (`after-err`, `pos-err` with correct position). Outer
context preserved, inner object does not leak.

### T2.2 ERRERR isolation — PARITY at Lua level (latent status leak, §2.5)
`p36_t22.lua`: co's handler errors → both engines: co's xpcall catches
`error in error handling` (the ERRERR is caught by the arming boundary — PUC
luaD_throw to the innermost errorJmp), co finishes, `resume1: false co-final`;
caller's handler-erroring xpcalls → `error in error handling`. The statically
proven err_is_errerr leak (§4.6) is not Lua-observable (status codes only).

### T2.3 C-function label — **DIVERGENCE (outcome A, real cross-thread leak)**
`p36_t23*.lua` verbatim (zig side; PUC shows `[C]: in global 'xpcall'` in
every case):

```
#23 (error inside resumed coroutine → later xpcall argerror):
ZIG: stack traceback:
     \t[C]: in global 'error'        ← stale label leaked ACROSS the resume
     \t/tmp/opencode/p36_t23.lua:7: in main chunk
     \t[C]: in ?
     (…printed twice — pre-existing double-traceback bug, see below)
PUC: \t[C]: in global 'xpcall'

#23b (no prior error — failC never presets a label):
ZIG: (no [C] line at all)  vs  PUC: [C]: in global 'xpcall'

#23c (pcall'd error() only, no coroutine — same-thread leak):
ZIG: [C]: in global 'error'  (stale from the RECOVERED error)

#23e (pcall'd assert):  ZIG: [C]: in global 'assert'
#23f (successful resume, no raise): ZIG: no [C] line (missing, not stale)
#23g (error inside resumed co): ZIG: [C]: in global 'error'  ← cross-thread
#23h (pcall'd string.format bad arg): ZIG: no [C] line (failLib clears label)
#23i (io.open bad mode, uncaught): ZIG: no [C] line  vs  PUC: [C]: in field 'open'
```

**Minimal reproducer (5 lines, `/tmp/opencode/p36_t23c.lua`)**:
```lua
pcall(function() error("plain", 0) end)
xpcall(print, "not-a-function")
```
**Root cause**: failC (vm.zig:6799) preserves `err_cfunc_label`; its
xpcall-bad-arg sites (20953/20956) never preset one; and no boundary except
closeThreadProtected saves/restores the field — so the label of the LAST
error()-family raise (any thread, any already-recovered error) survives into
the next failC traceback. PUC derives the frame structurally from the live C
CallInfo. Fix directions in §2.10/§6. (The doubled traceback in the zig
captures is the KNOWN pre-existing CLI double-traceback bug, STATUS.md
side-finding backlog — unrelated to the leak, reconfirmed identical at HEAD.)

### T2.4 shared-buffer alias (err → err_buf) — PARITY (hazard masked)
`p36_t24.lua`, three shapes: (a) caller's formatted level-1 error + TBC
`__close` that resumes an erroring coroutine during the unwind → pcall result
bytes = the ORIGINAL `A-MSG…` message in both engines; (b) xpcall handler
resumes an erroring coroutine → handled message intact; (c) nested
resume-in-closer inside a dying coroutine → the coroutine's own message
intact. Why masked (code-reading, §2.1/§4): pcall results come from
`protectedErrorValue` → `err_obj` (interned at raise, immutable); unwind paths
snapshot via `currentRuntimeErrorValue` BEFORE closers run and
`restoreRuntimeErrorValue` re-points `err` at the interned snapshot; handler
results re-derive `err` from the returned string. The slice-restore hazard in
builtinCoroutineResume (21755) is real as a representation hazard but no
observable path was found — every consumer between restore and next raise
reads interned objects or snapshots. BytecodeSavedError's 256-byte cap (§4.1)
is the same class: parked >256-byte messages truncate on restore, but the
truncated state is dead until the next raise overwrites it.

### T2.5 alternating threads A/B — PARITY
`p36_t25.lua`: 4 rounds of interleaved resume of two coroutines that pcall

yield payloads, and statuses identical in both engines, per-thread throughout.

### T2.6 successful inner resume inside outer error handler — PARITY
`p36_t26.lua`: outer xpcall handler resumes a yielding/returning inner

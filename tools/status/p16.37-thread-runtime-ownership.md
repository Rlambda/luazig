## T3 design decision — **Variant A** (Thread fields canonical)

**Choice: Variant A — Thread owns the runtime fields canonically; Vm keeps NO stack
state; every consumer accesses the owning Thread directly.**

Rationale (against Variant B — Vm keeps borrowed `active_runtime: *BytecodeRuntime`):

1. **PUC-first (AGENTS.md)**: in PUC Lua the stack lives on `lua_State` (`L->stack`,
   lstate.c) and `luaV_execute` receives `L`; `global_State` holds no stack and no
   "active stack" pointer. Variant A IS this model — `Thread.bytecode_stack` is
   `L->stack`, `activeBytecodeThread()` is `L`, the dispatch loop caches the thread
   like PUC caches `L`/`ci`. Variant B keeps a Vm-global borrowed pointer — a
   luazig-specific shadow of the old move ceremony with NO PUC analog.
2. **Invariant count**: A has ONE switch-state pointer (`current_thread`, null=main).
   B has TWO that must agree (`current_thread` ↔ `active_runtime`) — the exact class
   of dual-source-of-truth the current `active_runtime_thread` already suffers from
   (asserted at 10855-10856). A deletes the class.
3. **Switch cost**: A's switch = the `current_thread` store (already present at all
   4 sites) + `refreshHooksCached` (~12 i). B adds a guard + pointer store on top
   (~4 i more). The 151 i/cycle park+activate+zeroing cost dies in BOTH; A ≤ B.
4. **Hot path**: identical. Both cache a pointer at frame_loop entry (A: `ctx.th`,
   B: `rt`); both pay one dependent load per `bc_stack` re-derivation vs today's
   direct Vm field (A: `th.bytecode_stack`, B: `active_runtime.stack`) — verified in
   disassembly at T7.4. No per-opcode thread lookup is added: `ctx.th` is set at
   frame_loop entry next to `ctx.regs` and is stable for the whole dispatch
   invocation (a thread switch always unwinds the dispatch loop via
   ThreadSwitch/Yield — it never continues on a foreign runtime).
5. **Churn honesty**: B's rename is more mechanical, but A's per-site resolution is
   trivial at every site (ctx.th in dispatch, existing `th` params in per-thread
   paths, `activeBytecodeThread()` in cold paths). AGENTS.md forbids choosing the
   lower-churn path over the PUC-faithful architecture when both are viable.

Deviation from PUC in A: none architectural. Zig-native implementation notes:
fields stay plain slices/ArrayList on Thread (no grouping struct needed — grouping
was a B concern); `bc_stack_initial` stays a Vm config constant.

**Critical invariant (T4.5)**: ONE canonical owner (the Thread); no move-in/move-out
anywhere; `bytecode_stack.len == 0` is NOT an active-sentinel — it only means
"never activated" (lazy first-activation allocation, T4.2). All
`if (th.bytecode_stack.len > 0) th.bytecode_stack else self.bc_stack` branches
(gcPropagateOne 25871/25941, Cell.resolveStack, stackForThread) are deleted as
class, not patched.

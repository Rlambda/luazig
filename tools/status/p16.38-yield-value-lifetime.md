### 1.2 Where the 1081 i/it gap lives NOW

1. **Dispatch loop per-opcode cost: zig 1075 vs PUC 232 → ~+843 i/it — the dominant chunk**
   (frame_loop machinery, ctx setup, per-opcode switch, OP_CALL arg/outs staging, hook
   probes, condGc). This is the known dispatch-floor domain (see
   `historical-dispatch-floor-p16.10.json`), NOT the resume/yield transition functions.
2. **Transition functions: zig 614 (resume 357 + yield 136 + wrappers 64 + eligibility 57)
   vs PUC ~650 (poscall+precall+auxresume+coresume+resume+unroll+finishOp+yieldk+throw
   +rotate+xmove+checkstack+rawrunprotected+setjmp/longjmp)** → roughly parity. PUC's
   setjmp/longjmp + xmove/rotate costs offset zig's resume/yield machinery.
3. **The double value copy (Cut 3 target)**: 2× `InlineValues.setFrom` per cycle =
   `th.yielded.setFrom(args)` (vm.zig:21725) + `th.suspended_builtin_args.setFrom(...)`
   (vm.zig:21735) — 40k 16-byte memcpys, 46 i/it memcpy + ~15 i/it setFrom overhead
   ≈ **60 i/it (~3% of D)** removable by the span representation + Cut 3B.

KEY discovery: the hot cycle does NOT use the trampoline — `driveBytecodeCoroutineTrampoline`
runs once (fresh body); subsequent resumes re-enter via `builtinCoroutineResume`'s
unroll_loop → `runClosure` (~22541, 20000 calls) because the body is parked
`bytecode_inplace_suspended` with a Lua top frame.

## 2. Cut 3 — T3.1 classification of yield-arg storage per path

PUC reference (ldo.c:1006 `lua_yieldk`): the yielded values are the top `nresults` slots of
the yielding thread's stack, physically inside the yield C-function's CallInfo window
(`ci->func+1 .. L->top`); only the COUNT is saved (`ci->u2.nyield`). `lua_resume` reports
`*nresults = L->ci->u2.nyield`; the resumer (`auxresume`) `lua_xmove`s the values OFF the
suspended thread's stack immediately — from Lua the values are never observable on the
suspended coroutine. On the next resume, `resume()` → `luaD_poscall(ci, n)` turns the
resume args into the yield call's results.

luazig paths by arg storage:

| path | args location | span-safe? | decision |
|------|---------------|-----------|----------|
| direct fast path (OP_CALL/OP_TAILCALL arm → `callCoroutineBuiltinDirect`, vm.zig ~18350/18851) | `th.bytecode_stack` caller window `ctx.regs[a+1..a+1+nargs]` | YES | **span** |
| generic builtin C-frame path (`callBuiltin` after `pushBuiltinCFrame`) | `rargs_fresh` re-derived from `ctx.regs` — same caller window | YES | **span** |
| C API `lua_yieldk` (c_api.zig:1937 → `luaYieldKShared` vm.zig:6175) | `h.c_stack` ArrayList — not the bytecode stack | no | **owned copy** |
| debug-hook yield (`in_debug_hook`, hook frame popped at vm.zig:21752+) | hook frame window — frame is POPPED after capture | fragile | **owned copy** (also PUC: hooks cannot yield values) |
| `__close`-transport yield (`testc_close_metamethod_depth > 0`) | metamethod frame window; close transport is cold and delicate | conservative | **owned copy** |
| trampoline nested re-yield (`bytecodeCoroutineYieldStep` vm.zig:11094) | reads + dupes existing values | read-only | unchanged |

Classification is done in `builtinCoroutineYield` by an O(1) pointer-range check of the
`args` slice against `th.bytecode_stack.items` (are the args where PUC would have them:
on the yielding thread's stack?) plus the two conservative force-owned conditions above.

## 3. Cut 3 — T3.2 lifetime proof for the span

Live interval of the span: [child parks at yield] → [resumer's `builtinCoroutineResume`
tail (vm.zig:22803) copies to `outs` and clears]. Invariants:

1. **No Lua code runs inside the interval.** The chain is pure Zig: yield arm →
   `builtinCoroutineYield` (span set) → `error.Yield` → park → unwind through
   `runClosure` → resume catch → tail consume. No dispatch-loop iteration, no hooks,
   no metamethods (parking does not unwind the child's Lua frames; `error.Yield` is not
   an error — no `__close` runs).
2. **No GC step inside the interval** (same argument: `gcAutomaticStep`/
   `condGcFromDispatch` run at dispatch boundaries only). Exception: `error.ThreadSwitch`
   returns from `builtinCoroutineResume` WITHOUT consuming — the span survives across
   dispatch iterations → the GC thread-mark path must mark span targets explicitly
   (vm.zig:25845). Marking is idempotent with the frame's `live_reg_top` marking.
3. **The child's stack cannot move or shrink inside the interval**: no child execution
   (suspended), the resumer touches only its own stack/outs and the child's
   `resume_inbox` (a separate field, vm.zig:21624). The span stores INDICES
   (base,len into `th.bytecode_stack`), so even a hypothetical realloc cannot dangle it.
4. **No Lua-reachable mutator of the span slots while suspended** — this required the
   T4.1 debug parity fixes (section 4): after the window-bound fix, `debug.getlocal/
   setlocal` on the suspended coroutine cannot reach the parked call's argument
   registers, exactly as in PUC (where the values sit above the C frame's func slot and
   the C window is empty after the resumer's xmove).
5. **Clear-on-consume mirrors PUC's xmove-pop**: every resume tail (22803/22809,
   22767/22768, 22267/22273, error paths 22786) deinits/clears the span; `coroutine.close`
   and thread free (`clearThreadContinuationScratch`, `gcFreeObject`) clear it as `.none`
   (nothing to free).

Representation: `Thread.yielded: YieldedValues` — tagged union
`none | span{base: u32, len: u32} | owned(InlineValues)`. Invariant: `span`/`owned`
always carry len ≥ 1 (zero-value yield ⇒ `.none`), so the existing
`th.yielded.slice() != null` predicates map 1:1 to `th.yielded != .none`.
Thread size: `InlineValues` ≈ 88 B (cap 4 × 16 B + slice + len); union adds a tag —
`owned` keeps `InlineValues` (cold paths only), so the hot-path cost is 2×u32, and the
per-cycle setFrom memcpy disappears.

## 4. T4.1 — debug.getlocal/setlocal differential on suspended coroutines (PUC 5.5.0)

Probes: `/tmp/opencode/p1638/t41_debug_suspended.lua`, `t41_map_levels.lua`,
`t41_full.lua`, `t41_active_window.lua`. PUC model (ldebug.c:196 `luaG_findlocal`):
`n` is a 1-based SLOT index (`pos = base + n-1`); the name is the locvar active at that
slot, else `"(temporary)"`/`"(C temporary)"` iff `n <= limit-base` where
`limit = L->top` for the current frame, `ci->next->func.p` otherwise. The yield C frame
stays on top of the suspended coroutine with an EMPTY window (values xmove'd off).

Findings (PUC vs luazig current):

| # | case | PUC | luazig today | verdict |
|---|------|-----|--------------|---------|
| D1 | `getlocal(co,0,n)` suspended at builtin yield | nil (empty C window) | Lua frame locals (a, x) | **divergent — fix** |
| D2 | `getlocal(co,1,n≥k)` temp slots past the parked call's callee reg | nil (limit = callee reg) | exposes yield values as `(temporary)` | **divergent — fix (required for span safety)** |
| D3 | `setlocal(co,0,1,v)` | `"(C temporary)"`, writes a DEAD slot (unobservable: next resume's poscall overwrites; getlocal can't read it back) | writes the Lua frame's param `a` | **divergent — fix: report `(C temporary)`, no write** |
| D4 | `setlocal(co,1,n)` on temp slots holding yield values | unreachable (limit) | can write them; resumer unaffected (copy) | fixed by D2 bound |
| D5 | `getlocal(co,2,..)` deeper frames (yield inside pcall: pcall's `(C temporary)`=true at level 2, body local at level 3); out-of-range level → error | full chain walk + `level out of range` error | level cap 0..1, silent nil | **divergent — OPEN item** (needs C-frame window modeling in the level walk; see §6) |
| D6 | active thread, `getlocal(2,n)` on a caller frame with running callee | nil past callee reg | exposes caller's call args as `(temporary)` | **divergent — fix (same bound rule)** |
| D7 | hook-yield suspension: level 0 | interrupted Lua frame, full window | same | parity OK |
| D8 | `getinfo(co,0)` at builtin yield | C function `yield`, currentline=-1 | same | parity OK (Cut 1 era) |

Window-bound rule implemented (PUC `limit`):
`bound = A(code[fr.pc])` iff `code[fr.pc]` is OP_CALL/OP_TAILCALL AND the frame has a
live callee: for a suspended thread — `bytecode_inplace_suspended and
!yielded_from_debug_hook` (non-hook suspensions always park at the call that yielded);
for the active thread — the frame directly above in `call_frames` exists and is NOT a
debug-hook frame (a hook frame above means the frame is "current" in PUC's sense — full
window). The bound applies to the temp scan AND the current-instruction-destination temp.

## 5. Cut 3B — `suspended_builtin_args` double copy

`suspended_builtin_args` (vm.zig:2341) is written on EVERY builtin yield (21728-21739)
but read ONLY at vm.zig:29312 — the `debug.getlocal` branch reached when the suspended
thread has NO parked Lua frame (pure-C suspension: testC base `yield`/`yieldk`). On the
direct/generic/C-API-from-Lua paths a parked Lua frame always exists and the getlocal
path returns at 29301-29305 before reaching the read. Fix: write
`suspended_builtin_args` only when `threadCurrentParkedRuntimeFrame(th) == null` at
yield time. `suspended_builtin` (the ID, needed by `debug.getinfo` level 0) is still
written always. Kills the second 16-B memcpy per cycle.

## 8. Cut 3 implementation results (2026-09-11)

### 8.1 What was implemented

- `YieldedValues` union (`none`/`span`/`owned`, vm.zig:2169) replacing
  `Thread.yielded: InlineValues`; `Thread.yieldedValues()` (2442) and
  `Thread.yieldArgSpan()` (2466) accessors; all read sites converted from
  `.yielded.slice()` to `.yieldedValues()`; GC thread-mark marks span targets.
- Cut 3B: `suspended_builtin_args` written only when no Lua frame exists in
  `th.call_frames` (inline loop at the yield write site); `suspended_builtin`
  (the ID) still always written.
- T4.1 debug parity fixes: `debugTempCalleeBound` + `frames_above` parameter on
  `debugGetLocalFromBytecodeFrame`/`debugSetLocalInBytecodeFrame` (temp window
  bounded at the yield/call's callee register); level-0 fixes in
  `builtinDebugGetlocal`/`builtinDebugSetlocal` (empty C window: getlocal(co,0,n)
  → nil; setlocal(co,0,1) → "(C temporary)" with no write); active-thread bound
  via `debugFrameHasRealCalleeAbove` (debug-hook frame above = full window).
- **Resume/yield outs window 8 → 256** (found by the span GC probe): the fixed
  8-slot window silently truncated every `coroutine.resume`/`coroutine.yield`
  to 7 values (PUC returns all — its C stack IS the outs window). Result counts
  are unknowable at call time (resume returns the NEXT yield's values; yield
  returns the NEXT resume's args), so the fix uses the architecture's
  unbounded-result convention window (256, same as pcall/xpcall/wrap_iter/testC).
  Pre-existing on HEAD; verified `yield(unpack(t100))` now returns 101 values
  exactly like PUC (was 8).

### 8.4 PUC-faithfulness notes

- The span IS the PUC model: values live in the yielding thread's stack window;
  only the count+position are recorded (PUC `ci->u2.nyield` + the stack slots);
  the resume tail copies them out (PUC auxresume `lua_xmove`) and clears.
- Zero per-yield allocation on the hot path — PUC yields allocate nothing.
  Side effect: GC cycle timing shifts slightly (fewer allocations), which shows
  as the tracegc dot-count class of divergence in byte-diff lanes (§6) — the
  mandatory matrix gate compares stdout only and is unaffected.

# P16.39 — Dispatch/opcode cost matrix (Cut 2): kernels K1-K6, exact D-bucket attribution

Phase P16.39 Cuts 1+2. **No runtime changes** — measurements only.
Companion artifacts: `tools/perf/current-dispatch-floor.json` (Cut 1 floor),
STATUS.md P16.39 Cut 0/1 sections.

## 1. Methodology

- **Perf** (both engines): n-vs-2n differencing, median of 3 runs per point,
  `taskset -c 0 perf stat -x, -e instructions:u,cycles:u` (cpu_core rows;
  cpu_atom are `<not counted>` on this hybrid CPU). i/it = (median(2N) −
  median(N)) / N. Same method as `tools/perf_dispatch_floor.py`.
- **Callgrind**: `valgrind --tool=callgrind --dump-instr=yes` at N=20k and
  40k; per-address Ir slope (40k − 20k)/20k. Every reported address was
  verified to be an instruction start (objdump cross-check); each hot-path
  instruction executes exactly once per iteration, so slopes are exact
  integers. `callgrind_annotate` line output was REJECTED for bucketing:
  it double-counts inlined frames (annotated file sums ≈ 1.7-4x program
  totals) and its `=>` inclusive lines pollute line tables. Addresses →
  (file, line, function) via `addr2line -f -C`, with nearest-lower-address
  fallback for `?` entries (same function only).
- **Executed-opcode counts** (zig): `--stats <json>` (`VmStats`
  `instructions_by_op`, default-off counters; never timed with stats on),
  n-vs-2n slope. **PUC**: `luac -l -l` — bytecode shapes are IDENTICAL to
  zig (same opcodes per iteration; codegen parity), so ops/it is engine-
  independent.
- Binaries: zig sha16 `c134caa825828c37` (head 862bec7 + measurements),
  puc `d54bc45e1757b216`, both ReleaseFast/-O2.

## 2. Floor (Cut 1 recap, forloop_only = K1)

| engine | i/it | cycles/it | branches/it | IPC | ns/it |
|--------|------|-----------|-------------|-----|-------|
| zig    | 61.02 | 12.15 | 7.00 | 5.02 | 3.21 |
| puc    | 28.00 | 10.35 | 5.00 | 2.71 | 2.74 |

Exact executed path (callgrind, matches perf to 0.02):
- **zig 61** = head 13 (fetch 4: cur_proto+pc spill reloads, code.ptr, inst;
  gate 3: dispatch_gate movzbl+test+je; dispatch 6: op movzbl+and, table
  lea+movslq+add, jmp*) + FORLOOP handler 37 + jump continuation 11
  (pc-apply 6 + sigint 5).
- **puc 28** = head 5 (lea pc+1, fetch, mov, and, scaled-index jmp* — pc
  lives in a register, no gate, jmp* does the table addressing) + FORLOOP 23.
- **i/fetch (simple op) = 15** zig (head 13 + incq pc + back-jmp) vs **7**
  puc (head 5 + lea pc+1 + jmp*). Unchanged from P16.34 post-cuts.
- **sigint**: zig pays 5 i/back-edge (local flag testb+je + pending
  movzbl+test+je; CLI installs the handler so the local is true); PUC pays
  0 in this path (no hook installed → no hook check at all). Documented
  P16.10 T8 design; latency parity kept (both check only at back-edges).

## 4. D-bucket decomposition (zig, callgrind addr-exact)

Buckets: **W** opcode semantics (work PUC also does) · **D1** shared
dispatch head (fetch+gate+switch, vm.zig:14631/14659/14854) · **D2**
frame_loop entry/re-entry + ctx + FrameStack machinery · **D3** OP_CALL
front half (callee resolve, eligibility, child base) · **D4** Lua child
activation (pushStagedFast) · **D5** OP_RETURN/parent completion (opReturn1)

## 5. Key findings

1. **The builtin call path is the worst gap in the matrix (K5 3.31x).**
   zig D6 493 + D8 55 = 548 i/it vs PUC's entire C path ~132 (precall+poscall
   +marshalling). Largest single items: callBuiltin dispatch machinery 175,
   popBuiltinCFrame 45, pushBuiltinCFrame 58, CallFrame-init memset 38,
   freeCFrameOwnedState 23, condGcFromDispatch+gcAutomaticStep 55 (the GC
   guard runs on EVERY builtin call — `gc_steps_auto` slope is exactly
   1/call; PUC checks GC only at allocation sites).
2. **K6 (2.10x)**: coroutine machinery D9 658 + builtin staging D6 449 +
   double frame_loop D2 256. Note the parity WINS buried in PUC's 980:
   PUC pays luaH_getshortstr 101 (global `coroutine`/`resume`/`yield`
   lookups are real calls) and setjmp/longjmp 89 per resume+yield pair;
   zig's GETFIELD fast path and error-return model pay ~0 and ~0
   respectively for the same work.
3. **K4 (1.76x)**: call+return machinery D3+D4+D5+D2 = 245 i/it vs PUC
   precall 48 + poscall-share. opReturn1's parent-completion path (D5 92)
   and pushStagedFast (D4 44) are the concrete targets.
4. **Head (D1) is a uniform but secondary tax**: 13 vs 5 i/fetch, i.e.
   +8/ dispatched op (2 spill reloads + 3 gate + 3 table addressing).
5. K3's 0.5 JMP/it confirms donextjump parity (taken side never fetches
   the paired JMP).

## 6. Ranked first-production-cut recommendation (estimates from buckets)

- **C. OP_CALL/builtin residue (K5-class)** — biggest absolute gap:
   pushBuiltinCFrame/popBuiltinCFrame/freeCFrameOwnedState + CallFrame
   memset + per-call GC guard ≈ 280-550 i/it on builtin-heavy code
   (K5 830 → est. ~450-550; K6 D6 449 → est. ~250-300). PUC-faithful
   direction: C-frame push should write only the fields PUC's prepCallInfo
   writes (no struct zero-init), and the post-builtin GC check should
   match PUC's allocation-site-only checkGC.
- **B. parent-return/re-entry convergence (K4-class)**: D5 92 + D4 44 +
   D2 44 = 180 vs PUC ~70-90 for the same call+return. Target: single-copy
   return fast path + cheaper re-entry (est. K4 395 → ~320-340;
   lua_calls 450.60 → est. ~380-400).
- **A. code_ptr+index-pc cache (head 13 → ~10)**: kills the cur_proto/pc
   spill reloads; uniform −3 i/fetch on EVERY dispatched op (K1 61 → ~58,
   K2 101 → ~95, K6 −33). Smallest absolute win of the three; keep the
   P16.35 pre-registered strict reject rule (any arith wall regression →
   REVERT).

Recommended order: **C → B → A** (data-driven; the p16.10 "dispatch floor"
track assumed A was the dominant gap, but the matrix shows the builtin and
call paths dominate every non-floor workload).

# P16.42 T3 — gc.lua "pace of the collector" hang (without --testc): CLOSED (fixed)

Date: 2026-09-12. HEAD at investigation start: 0728e37 (P16.42 Cut 1).

## Symptom

`gc.lua` (upstream testes) hangs (300s timeout) when run WITHOUT `--testc`,
inside the pace-of-the-collector section (gc.lua:204-217, `if not _port then`).
With `--testc` the same file passes. ReleaseFast and Debug both hang.

## Root-cause chain (measured, not guessed)

1. Instrumented trajectories (`/tmp/opencode/gc_diag.lua`): after
   `collectgarbage(); collectgarbage()` the baseline `x = collectgarbage("count")`
   collapses to ~0. LOOP-1 (`while gcinfo() > 3*x` style) exits immediately
   (any memory > 3×0); LOOP-2 (`until gcinfo() <= x*2`) can NEVER exit —
   the bar `2*x = 0` is unreachable while the loop allocates.
2. Bisect via truncated gc.lua copies: count is normal (20.966 KB) after
   line 75, but 0.000 after the "creating many objects" section (126-156);
   isolated to the `load` loop (147-152):
   `load(string.format("function temp(a) return 'a%d' end", i), "")()` × 5000.
3. Minimal repro (`gc_load.lua`): count degrades monotonically with n:
   21.33 KB (n=1) → 13.53 (1000) → 5.72 (2000) → **0.0000** (5000).
   PUC stays ~19.86 KB.
4. Drift probe (`gc_drift.lua`, 5×200 loads): exactly **−1600 B per 200
   loads = −8 B/load**, forever. PUC: one-time −880 B, then stable.
5. Tree accounting EXONERATED first: env-gated instrumentation of
   `chargeTreeFootprint` (vm.zig) vs `releaseTree` credit (bytecode.zig)
   showed CHARGE == CREDIT == 663 B per load — symmetric.
6. Decisive instrument: ordered event trace of every `gcNoteAlloc`/
   `gcNoteFree` (return-address keyed, env-gated, temporary) for ONE
   isolated load between two full GCs. Trace showed:
   charge `+40` for the chunk closure, later sweep free `−48` for it.

## The bug

`createBytecodeChunkClosure` (vm.zig, text-load path) charged

```zig
self.gcNoteAlloc(@sizeOf(Closure));           // 40
```

but `gcFreeObject(.closure)` credits

```zig
self.gcNoteFree(@sizeOf(Closure) + c.upvalues.len * @sizeOf(*Cell));  // 40 + n*8
```

A main chunk closure has exactly 1 upvalue (`_ENV`) → **charge 40, credit 48
= −8 B per `load()`**. After ~150 loads the accumulated under-report skews
`gc_count_kb` enough that a full `collectgarbage` drains the counter to 0;
from there gen-GC pacing (thresholds derived from the count) and the pace
section's `x*2` bar collapse.

Same missing term in `closureFromProto` (undump/binary-load path).

PUC parity: `luaF_newLclosure` allocates `sizeof(LClosure) + nupvals*sizeof(Upval*)`
as ONE block charged via `luaC_newobj` — the charge must cover the upvalue
pointer array. The other two closure-creation sites already did this
(`runBytecodeInternal`: `@sizeOf(Closure) + upvalues_in.len*@sizeOf(*Cell)`;
OP_CLOSURE: `@sizeOf(Closure) + nups*@sizeOf(*Cell)`).

## Fix

Both sites now charge `@sizeOf(Closure) + n*@sizeOf(*Cell)`; the matching
`errdefer` unwind paths free the same total AND free the upvalues array
(previously `destroy(cl)` alone leaked the array on the OOM path).

## Verification

- Single-load probe (`gc_trace1.lua`): count delta **0.0 B** (was −8.0).
- `gc_load.lua` n=5000: count **21.30 KB stable** (was 0.0000).
- `gc_drift.lua`: flat after first round (one-time −29 B warmup, PUC-shaped).
- **gc.lua WITHOUT --testc: PASSES, output byte-identical to PUC** (was hang).
- gc.lua WITH --testc: passes, output unchanged vs pre-fix.
- gengc/tracegc/locals (--testc): outputs byte-identical to pre-fix
  (gengc/locals vs-PUC diffs are pre-existing at HEAD, verified via stash).
- Collateral symptom fixed for free: `T.stats()` after ≥150 loads + full GC
  crashed (`switch on corrupt value` in ltable keyMatches) — the collapsed
  count lowered the GC threshold so a step fired mid-`builtinTestcStats`
  and swept its not-yet-rooted Zig-local tables. With honest pacing this no
  longer triggers at any N (tested 150/200/500/5000). NOTE: the latent
  rooting hole in `builtinTestcStats` (tables held only in Zig locals across
  allocating `setField` calls) still exists in principle — flagged for the
  C-frame/GC-rooting convergence work, not fixed here.
